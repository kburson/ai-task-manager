# GraphQL usage inventory and record contract

Issue #1835 establishes the source inventory and metadata contract for epic #1818. It does not collect traffic. Source detections are code locations, not observed network requests or point costs. The checked inventory is in `scripts/task-tracker/lib/graphql-usage/inventory-expectations.json`. `scanGraphqlSurfaces` returns relative source locations and reasons; `compareInventory` fails when a file and classification count or an exact source location changes without updating the reviewed expectation.

At the reviewed scan, 253 source detections were classified: 128 explicit GraphQL CLI or shared `gql` wrapper sites, 43 opaque high level CLI candidates, 46 uncovered dynamic wrapper or shim sites, 33 static command text mentions with no dispatch evidence, 2 REST or other non GraphQL sites, and 1 direct HTTP endpoint. The 25 direct `gh api graphql` sites in `scripts/gh/init-project-config.sh` are individually detected. The synchronous call in `scripts/gh/verify-priority-p3.mjs` and the direct HTTP endpoint in `scripts/reports/generate-value-report.mjs` are also detected. Counts are source review aids only; one source site may issue zero or many requests at runtime. Static command text requires human review if its use changes.

The uncovered set includes `scripts/task-tracker/action-capture-bin/gh`: the existing shim launches the real executable but does not yet write usage observations. It also includes dynamic `run('gh', args)` wrappers such as `scripts/gh/create-issue.mjs`; the source scanner cannot determine their request class from the local call line. Task 3 must add collection at that existing boundary. Direct shell or script execution without a measurement launcher or inherited collection context is also uncovered. Absolute `gh` executable paths and environment selected executables that bypass inherited `PATH` are classified as uncovered when detected; none appeared in the initial production scan. High level `gh issue`, project, and other CLI calls remain opaque because their internal GraphQL attempts, retries, and pages are not observable from their caller. Task 3 must report them as opaque invocations, not as one HTTP request each.

`graphql-usage/index.mjs` exports the versioned observation, diagnostic, manifest, and inventory validators, plus safe operation identity. Records accept only declared fields and bounded metadata. Query text, variables, request and response bodies, issue text, tokens, raw exception messages, raw paths, and raw session values are refused; session attribution must use a SHA-256 identifier. A null `pointCost` requires an explicit `costUnknownReason` and `costCoverage: unknown`; a supported same response query cost uses `costSource: same-response-rate-limit` and labels the instrumented request. Complete known cost is limited to an observed HTTP attempt with zero hidden requests; an opaque invocation can retain only visible-response-only known cost. Missing rate-limit headers require a bounded unavailability reason, and inherited launch routes retain their origin. A fingerprint hashes the normalized GraphQL token stream after string, numeric, enum, boolean, and null values are replaced. A conservative GraphQL grammar check declines malformed documents. Parse failure returns unknown identity, allowing the original GitHub operation to proceed unchanged.

Task 2 can use the validators as its storage boundary. Task 3 can reconcile every launched path against this expectation file and update coverage from planned or opaque to observed only after integration tests prove the corresponding launch route. New paths must be classified deliberately; an unchanged source inventory cannot prove complete runtime coverage, and a same-line replacement still needs review for semantic changes.
