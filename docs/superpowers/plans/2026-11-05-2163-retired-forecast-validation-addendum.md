# Retired forecast validation addendum for #2163

Status: proposed; independent manual SAR pending. No dependent production change is authorized by this document alone. The accepted specification at `05c4f86cb1aa07d4445c9e5f576df9af6782f823` and accepted implementation plan at `35002c59cb62585917b5ca6b7fdc86a1ad53dcd3` retain their exact bytes and original acceptance. This narrow addendum proposes a correction to Task 2's pending-validation constraint; it introduces no recovery command, caller authority, schema, lifecycle change, collector change or owner change.

## Observed incompatibility

The new unit regression `scripts/tests/unit/task-tracker/lib/inflation-retired-forecast.test.mjs` runs the actual `runCancelPlan` against the existing cancellation harness with a valid production-parsed forecast, then calls the actual candidate `runInflateEstimate`. Cancellation completes. Inflation currently returns partial with `inflate-estimate:pending-source-drift:sources`; the retained run is `.scratch/test/2163-retired-forecast-red.log`. This is unit evidence using fixture ports, not public-entry or native host proof. Original full-source behavior for this specific case has not been independently executed.

The shared writer already carries `retired-forecast` and `retired-ready` read-only adapters into a subsequent publication. They retain the forecast record ID/hash and ready-marker absence; their apply methods throw on drift. New publications initially persist those effects pending and later confirm them through real readback. The real collector can therefore report `readForecast.status = unavailable`, with the existing exact `publicationTransition` record, until retirement and before-record confirmations or field convergence make retirement observable again. Intermediate board/body changes can also return to this state. The publication owner already handles this narrow transition through `publicationForecastTransitionUsable`. The reviewed plan's requirement that every source be observed and the sole incomplete reason be `authority-conflict` unintentionally excludes it from the new inflation validator.

## Proposed bounded comparison

Keep ordinary pending validation unchanged. Add one explicitly proved exception for the existing retained-forecast transition, entirely inside the inflation-specific pure comparison. It must satisfy every condition below before any unavailable source or incomplete reason is accepted:

1. All sources other than `readForecast` are observed with exact full hashes. The forecast has a full matching value hash; its only permitted non-observed status is `unavailable`. Its value has the real reader's closed fields, including its exact `publicationTransition`. Current metadata, subject, proposal, sealed before-record, actual issue body, complete raw comment identities, board/body snapshots and all business-effect permitted digests pass the existing checks. No malformed projection or other unavailable reason is allowed.
2. Production record parsing and projection prove exactly one active forecast, no ready marker, and no selected ready forecast. The record ID, payload hash, estimate and size match the current forecast observation. The retained ID/hash exactly match the sealed before-record forecast baseline. Recompute the expected transition using the existing pure `forecastPublicationTransition` with the actual parsed records, ready-marker absence, projection and proposal-parser availability; require exact equality to the observed transition. Reasons must be exactly `forecast-unavailable`, optionally accompanied by `authority-conflict` from the already checked permitted intermediate projections. A ready forecast, missing/ambiguous record, changed record, malformed transition or any other reason refuses.
3. The current publication and before-record both contain the registered `retired-forecast` and `retired-ready` effects with their exact IDs, resources, targets and intended hashes. Their sealed before/intended/permitted hashes must bind the actual retained ID/hash and actual ready-marker absence. Confirmed effects must have matching observed hashes. These are the existing read-only adapters; do not create a new effect or call their throwing apply methods. The stored before-record must match its own sealed descriptor and valid original field/forecast baselines even while its confirmation is pending.
4. Reparse current comments in their actual current publication context. Preserve the actual absence of `published`; never pretend a retired record is a ready forecast. Require available proposals exactly equal to the current authoritative forecast proposals, including full hashes. Keep the existing non-target proposal equality rule.
5. In the temporary completed comparison only, project the four inflation effects and the three already present read-only confirmations (`retired-forecast`, `retired-ready`, `writer-before-values`) to their exact intended hashes. Keep publication status pending, all identity/time/sealed fields, supersedes and unrelated effects unchanged. Confirm the completed projection satisfies the existing retirement predicates using the proven record and absent ready marker. The `writer-before-values` confirmation reflects the exact record already physically observed, not a fabricated write.
6. Remove only the now-proven transient `publicationTransition` property from the cloned forecast value; preserve every record identity, payload value, unrelated proposal and source observation. Apply ordinary size/estimate projection, production completed-context proposal parsing and full hashing, then compare only to the immutable prior intended digest. Return no replacement input/digest and persist none of this temporary projection. The actual collector remains unavailable until real confirmations/convergence occur; the real owner and final full collection remain mandatory.

This is an additional explicitly validated intermediate state, not general acceptance of unavailable authority. The package callback still runs after adapter/effect checks and fresh real collection before any retry persistence, and at existing effect checkpoints. Matching prior derivation remains disabled.
