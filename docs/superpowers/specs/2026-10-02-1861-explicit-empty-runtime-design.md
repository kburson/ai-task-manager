# #1861 explicit empty runtime reassessment

Status: proposed architectural amendment, not approved or implemented. This records a gap in the existing C1 acceptance contract, not a claim that #1861 is complete.

## Intent and evidence

An operator whose complete runtime authority is absent needs a registered, explicit path to initialize a new generation without restoring grants from stale legacy data. Partial loss, existing journals, unknown records and uncertain writers must remain protected blockers. The accepted parent contract requires total absence before empty initialization and canonical reconciliation; ordinary commands must never initialize implicitly.

The current linked-worktree initializer requires an activated main generation and rejects roots included in the original migration. Main migration planning returns `canonical-reconciliation-required` when there are no sources. Neither supplies a main/total-loss initialization primitive. The earlier C1 design's statement that a proven-empty case was already admitted is unsupported by current source. Empty initialization cannot be implemented by creating fake legacy inputs, editing authority records manually, or suppressing those blockers.

## Alternatives and recommendation

A. Add a separate protected empty-initialization protocol, exposed through the existing registered initialize commands. This preserves the current migration and linked-initialization contracts and gives absence its own exact approval and recovery proof. Recommended.

B. Extend migration plans with synthetic records and an empty-source policy. This shares publication code but mixes trusted source copying with generated empty records and broadens migration validation. It requires a new migration-plan version and more compatibility work.

C. Retain the current typed refusal and defer the capability. This preserves evidence but leaves the accepted main/total-loss outcome unimplemented; it cannot be reported as completed C1 acceptance.

## Exact candidate interface

Add `planEmptyRuntimeInitialization({ projectRoot, mainRoot, adapters })`, an asynchronous read-only planner, plus `applyEmptyRuntimeInitialization({ plan, approvedPlanDigest, adapters })`, `inspectEmptyRuntimeInitialization({ projectRoot, mainRoot, operationId })` and `resumeEmptyRuntimeInitialization({ projectRoot, mainRoot, operationId, observedDigest, approvedPlanDigest, adapters })`.

The plan schema is a new `aitm.runtime-empty-plan/v1`, rather than reinterpreting the existing linked initializer's v1. It binds the physical main owner, complete registered-root census and identities, exact absence observation, complete writer census, fixed no-grant records and digest. It contains no caller-selected record targets or replacement payloads. Only the main physical worktree can admit an initial empty generation. Unavailable or aliased registered roots, unknown writers and other claims block.

Prove absence across every participating root's durable runtime and known historical authority locations, including .db/aitm, .tmp/aitm and supported .ai-task-manager/.claude state families. Configuration and documentation are outside authority inventory. Populated authority, unresolved locks, malformed or unsupported records, existing protected journals, unknown publication artifacts and partial surviving controls/stores block. An empty directory is not automatically proof that an unresolved lock can be erased.

The fixed publication creates local state `{}` and queue `[]` in every root, plus fleet `{}` and occupancy `{}` in the main root. It creates no active binding, actor time, gate approval, occupancy, issue claim or delivery authority. Canonical issue/session reconciliation remains a separate normal workflow; initialization itself grants nothing.

The protected journal schema is `aitm.runtime-empty-initialization/v1`, under the main durable runtime's own empty-initialization namespace. It captures all physical identities, original absence, exact generated bytes, genuine owner, owner history and prepared/publishing/complete state before stores or controls are published. A distinct `aitm.runtime-control/v2` binds that journal; v1 controls and their migration/linked-initialization proofs remain readable. The shared control chooses the activation proof kind. A common read-only activation-root result lets a subsequently registered linked worktree use its existing separate initialization without fabricating a migration manifest.

Existing bootstrap grammar is extended explicitly: main-root `initialize-plan` returns the new plan union; `initialize-apply` validates its exact type/digest and fresh observations; read-only `status` exposes empty journal observations; empty `initialize-resume` requires the exact observed digest and operation ID in addition to the approved plan. Existing linked v1 arguments retain their current semantics. Parser, descriptor/help and physical handler must agree; no free-form payload, PID, override or path supplies authority.

## Publication and recovery

Serialize through the protected main-owner coordinator before rechecking the complete absence/census. Once that exact coordinator is acquired, its own generated record is an admitted artifact, not evidence of preexisting authority. Any unrelated mutation refuses before publication.

Publish the complete journal first, stage fixed bytes on each destination filesystem, verify them, rename each store, and publish each control before marking the shared journal complete. Ordinary reads refuse throughout prepared/publishing status, including partially activated controls. All roots and controls must agree before completion admits reads.

Resume uses the exact observation, genuine original owner or normal confirmed exact-owner death, and the normal observed coordinator recovery route. Validate the whole set before writes: each destination is either the approved original absence or the exact protected staged/published outcome. Changed bytes, aliases, generations, physical roots or conflicting artifacts refuse and preserve evidence. Pending journal/control publication must have an exact protected predecessor and original payload; uncertain artifacts are never deleted to unblock. A killed resumer records its own genuine owner. Completed retry cannot replace later valid state or undo a proven successor generation.
