## Proposed proof

Author's bounded design choice: retain the existing exact/disjoint tree proof and add an already-applied-prefix proof only at the existing overlapping-entry indeterminate branch for complete accepted-source comparisons. Existing true and definitive false results remain final; do not run a fallback that overrides false. P=source base is the existing exact case, and P=accepted head is the existing no-content case; both stay with that proof rather than the new strict-interior-prefix search. Do not build a general merge engine.

The comparator receives private read-only access to the actual selected PR's complete source-commit evidence from its existing production closure. Bind its canonical immutable observation identity to the exact sourceCommitEvidence consumed by the v5 verifier and refuse a changed view. This is observation data, not a permission token. It must not accept CLI flags, environment-selected proof data, arbitrary callbacks or a replacement receipt. The existing observed-integration verifier must validate the source inventory before content comparison; the new proof independently correlates any candidate to physical immutable Git objects and source ancestry.

For a candidate already-applied prefix:

1. The requested source head must equal the exact accepted PR head. The complete source inventory must be available and belong to that same observation. Do not apply this extension to individual `rebase-step` comparisons or invent a partial inventory.
2. Read the actual integration-base tree. Consider only commits in that validated source inventory that are genuine ancestors of the accepted source head and descendants of the requested source base. Correlate actual commit identity/tree/parents with the observed evidence; missing or contradictory objects refuse.
3. Require the candidate's **entire tree**, including paths, modes and object identities, to equal the integration-base tree. Equal content in one overlapping file is insufficient. The source ancestor and integration base may have different commit identities because squash delivery is the motivating case.
4. Require the observed integration-head entire tree to equal the exact accepted source-head tree. Combined with the full prefix equality, this proves the result of applying the remaining accepted source suffix to the already-applied prefix. Final-tree equality alone never admits the case.
5. Return the same comparison truth value through the existing verifier. Preserve the original quartet, source mapping and byte-exact receipt. No new successful lifecycle marker or alternate content-proof schema is produced.

If no prefix is proven, the current conservative proof/refusal remains authoritative. A source prefix plus unrelated integration-base changes is outside this narrow extension unless the existing disjoint proof already establishes the result. Do not turn unavailable or ambiguous proof into success. Multiple equivalent prefix candidates are harmless only when each admitted candidate independently proves the same complete-tree and ancestry facts; a conflicting observation refuses.

All Git access remains confined to existing read-only transport and immutable identities. No `merge-tree --write-tree`, fetch, update-ref, object/index/worktree writes, mutable branch substitution, source rebasing or implicit provider mutation. Avoid a new runtime leaf unless source analysis proves it necessary; measure any package delta rather than raising a ceiling speculatively.
