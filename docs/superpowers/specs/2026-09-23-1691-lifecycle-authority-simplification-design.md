# Lifecycle Guard and Authority Simplification Research

**Issue:** #1691

**Baseline:** `601db6e51831dbd6f3d26566facc0aeb9d9a3055` (`origin/trunk`, after #1558)

**Disposition:** Architecture recommendation. This document authorizes no runtime change or guard removal.

## Decision

Keep #1558's `action-decision` evaluation as the shared readiness boundary. Concentrate the next change on one **terminal Review authority** result consumed by Review re-entry, approval, delivery, and close. That result must distinguish `passed`, `waived`, `blocked`, and `indeterminate`, identify the exact accepted Test head, and retain the workflow-exception record ID and revision for a waiver. Collectors may read different evidence protocols, but consumers should not reconstruct a terminal verdict from a checkbox, timing row, or live waiver independently.

The second priority is to make the evidence-source contract explicit. The legacy issue body, GitHub directory records, and evidence-v2 journal are current compatibility lanes with different authority rules. A single typed source-selection result should describe their relationship and refuse an ambiguous combination. Do not collapse them by treating a display marker as a durable record. Static skill and guidance text remains presentation; commands and effect-time validation remain authoritative.

## Scope and method

The inventory covers state movement, Test, Review, approval, delivery, close, workflow exceptions, evidence carriers, and installed guidance. It follows executable imports and boundary calls at the pinned baseline, not historical diagrams alone. Code paths in the table are relative to `scripts/task-tracker/`; line references describe the pinned commit. The source set is intentionally that production path plus the delivered #1005, #1624, and #1558 specifications. Tests and fixtures are used as oracles, not counted as independent runtime decisions.

For the counts below, an **independent predicate** is a production branch or function that can accept, refuse, or redirect the same semantic condition by inspecting raw evidence or a partial boolean instead of consuming the shared typed decision. A source adapter that only retrieves or validates a carrier is counted separately. A guard registration on multiple state edges is _not_ automatically a duplicate predicate. A consumer-specific branch is counted only when its outcome can alter the lifecycle action, not when it formats a message.

The table distinguishes a source **locator** from a source **authority**. For example, `authority-locator.mjs` explicitly classifies which lane applies; the directory record resolver establishes authority. `evidence-v2/protocol.mjs` validates a projection and execution context; the journal supplies the underlying event record. Similarly, the `Agent Review Passed` checkbox is evidence of an ordinary pass only under its gate's proof grammar; a waiver must remain `waived` and must not tick it.

## Target architecture

1. **Retain static policy owners.** `lifecycle-policy` owns state/action topology. `workflow-policy` owns requirement IDs, exception validation, and constraints. Neither YAML guidance nor a consumer verb defines alternative policy. A catalog-to-consumer coverage test should refuse a newly added requirement without an explicit applicability mapping.
2. **Collect a typed, immutable authority snapshot.** Extend the existing `action-decision` observation ports with a source descriptor that says `legacy-body/v1`, `github-records/v1`, or evidence-v2 with its projection/journal context. Characterize combinations before choosing precedence: a v2 projection and directory marker may represent distinct layers, so merely preferring one marker would be unsafe. Unreadable, conflicting, or duplicate carriers yield `indeterminate`.
3. **Resolve one terminal Review decision.** Extract a source-independent `resolveTerminalReviewAuthority` from the proven #1683/#1690 logic. Inputs include issue/repository/scope, accepted Test SHA, one canonical terminal Review event or pass proof, current exception decision, and source provenance. Return a closed discriminated result: `passed` (real pass proof), `waived` (exact requirement plus record ID/revision and head), `blocked` (known failure/missing evidence), or `indeterminate` (unreadable/ambiguous/stale authority). Do not return a bare `agentReviewPassed`/`semanticReviewWaived` boolean to action consumers.
4. **Use the result at every boundary.** Review self-loop verification, `approve`, Review-state `promote`, delivery readiness/preflight, and close use the same terminal decision. Each retains its extra action-specific protections: approval provenance, provider denial, unique PR and CI, delivery receipt, trunk attribution, ownership, and child disposition. Explanation and execution consume the same decision contract, but execution reloads authority under its existing lock immediately before effects.
5. **Project evidence only after a decision succeeds.** Keep historical `review:failed` rows; retire only the active failure carrier after a successful pass or waiver. The body checkbox, timing row, audit comment, and compact guidance response are typed projections or presentation. An approved waiver never becomes a passed review, and Full-Auto never becomes a workflow exception.
6. **Delete compatibility branches in stages.** First characterize ordinary pass, current waiver, stale/revoked/wrong-scope/wrong-head waiver, unresolved failure, missing timing, ambiguous comments, v1/directory/v2 source forms, and approval/CI/close restrictions. Add the shared loader and resolver, migrate one consumer at a time, compare explain versus execution, then remove consumer-local switches and redundant fetches. Convert frozen legacy refusal sites to typed codes with the existing lint gate; do not remove the inventory until it reaches zero.

## Acceptance checks for the later overhaul

- Parity fixtures must demonstrate all seven #1558 action lanes and the unchanged 49-registration baseline behaviors before any guard deletion. A reduced registration count alone is not a pass condition.
- Every affected action must return `blocked` or `indeterminate` for stale, malformed, revoked, wrong-issue, wrong-scope, wrong-head, missing, or ambiguous Review/exception evidence, with no effect before refusal.
- A valid waived Review must be usable by approval, delivery, close, and Review-state navigation without setting Agent Review Passed; an ordinary passed Review remains valid with the same exact-head proof.
- Read-only explanation and `workflow-preflight` must not write markers, launch a provider, or cache live authorization. Execution must refetch and revalidate under the relevant lock after an intervening authority change.
- Approval audits must reflect the session's actual Full-Auto mode. A no-flag default must not create a human provenance claim. Existing explicit human approvals remain human.
- The scoped metrics above must reach their targets with the old branches and redundant readers removed, and with no growth in unclassified legacy refusal sites. Report source SHA, counted sites, fixtures, and request-count deltas alongside any claimed reduction.

## Risks and deferred decisions

An eager universal evidence parser could erase the deliberate separation between legacy body, directory, and v2 journal authority. A typed source descriptor should be adopted only after fixtures establish mixed-marker semantics and upgrade/reopen behavior. The terminal Review resolver should own the semantic verdict while keeping provider execution, human approval, PR protection, and delivery as separate decisions. Current safeguards must remain fail-closed during partial migration. This research does not schedule an overhaul or create implementation sub-issues; those require a separate approved plan from the pinned findings.
