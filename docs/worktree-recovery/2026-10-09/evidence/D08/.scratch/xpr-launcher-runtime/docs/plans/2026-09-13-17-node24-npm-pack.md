# Node 24 and npm Pack Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the Node 24 migration by strictly accepting the observed npm 11 and npm 12 single-package pack-report shapes, proving both in CI, and documenting the pre-1.0 compatibility release.

**Architecture:** Keep npm process invocation and pack-report interpretation in `test/helpers/npm-command.mjs`. The parser normalizes only the two observed outer shapes and then applies one shared inner-report contract; packaging and smoke select whether `filename` is required. Repository-policy tests independently lock package metadata, workflow runtimes, npm-major lanes, and release notes.

**Tech Stack:** Node.js 24+, npm 11/12, `node:test`, GitHub Actions YAML, JSON fixtures.

**Spec:** GitHub issue #17 and its mirrored Deep-Dive Analysis.

## Global Constraints

- The supported Node.js runtime floor is exactly `>=24`; Node 26 remains the preferred local runtime through `.nvmrc`.
- Parsing is based on JSON shape, never `npm --version`.
- Exactly one report for `ai-peer-review` is accepted.
- An npm 12 object key and the inner report `name` must both match the expected package.
- `files` is always required; `filename` is required only by consumers that construct a tarball path.
- CI pins npm 11.8.0 and npm 12.0.2 for reproducible compatibility evidence.
- The Node-floor change is documented for the planned `0.3.0` pre-1.0 release; this story does not rewrite historical release provenance.

**Interfaces:**

- [ ] **Step 1: Add observed-shape and refusal fixtures**

  Use minimal report objects with `name`, `filename`, and `files`. Preserve invalid JSON literally in `malformed.txt`; represent empty/multiple output with arrays; use the npm 12 keyed object for the unexpected-name case.

- [ ] **Step 2: Write failing unit tests**

  Cover npm 11 array success, npm 12 keyed-object success, malformed JSON, empty and multiple reports, a non-object outer value, unexpected object key, mismatched inner `name`, missing `files`, and missing `filename` under both `requireFilename: true` and `false`.

  The wished-for call shape is:

  ```js
  parseNpmPackOutput(fixture('npm-12-single.json'), {
    expectedPackageName: 'ai-peer-review',
    requireFilename: true,
  });
  ```

- [ ] **Step 3: Run the focused test and verify RED**

  Run: `node --test test/unit/npm-pack-report.test.mjs`

  Expected: failures show the existing helper accepts wrong names or incomplete reports and does not support the options contract.

- [ ] **Step 4: Implement the minimum strict normalizer**

  Parse once; accept only a one-element array or a one-key non-array object; bind the object key to `expectedPackageName`; require one plain report object; require exact `report.name`; require an array `report.files`; and conditionally require a non-empty string `report.filename`. Wrap JSON parse failure with an npm-pack-specific message while preserving the cause.

- [ ] **Step 5: Run the focused test and verify GREEN**

  Run: `node --test test/unit/npm-pack-report.test.mjs`

  Expected: all parser cases pass.
