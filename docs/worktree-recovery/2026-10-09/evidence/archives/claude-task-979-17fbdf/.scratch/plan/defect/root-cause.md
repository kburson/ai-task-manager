Two independent causes compose into a dead end.

**1. The reconcile lane is gated on there being no intent.** In `scripts/task-tracker/verbs/deliver.mjs` the merge-method reconciliation block sits inside `if (liveIntent === null) { ... }` (the `#1562` block). It therefore only runs for already-merged external recovery where AITM never authorized an intent. When AITM did authorize one — the normal governed path — `liveIntent` is non-null, the block is skipped, and verification compares the observed topology against the pending intent's `mergeMethod`, refusing at `delivery-verification.mjs` (`mergeMethodObservation !== intent.mergeMethod`). The `close` refusal text advertises the flag unconditionally, so guidance and reachability disagree.

**2. Delivery refusals are not addressable, and the delivery family is sealed.** `catalog.mjs` marks all ten `delivery.*` requirements `waivable: false`, and `validateWaiverIds` refuses a non-waivable id, so `workflow-exception` — the existing generic human-authority mechanism — cannot reach any of them. Worse, `merge-method` is not a catalog item at all; it is a bare `verificationError('merge-method')` throw, as are `merge-method-observation`, `merge-method-unknown`, `merge-method-evidence`, `expected-head-sha`, `base-ref` and others. Even opening the family would not make these reachable.

The deeper design problem is the one the operator named: the codebase has been answering each unforeseen divergence with a new special-case branch. That does not scale, and every branch is itself a place a false green can hide. What is missing is a single generic lever whose use is recorded as a human decision.
