## SAR-R1-F002 — P1 — Make envelope requirements conditional on actual evidence and input form

**Location:** Selected review producer/consumer envelope, lines 126–140; durable outcomes at line 113; draft publication at line 160.

The revised contract is materially stronger, but three universal field requirements conflict with supported histories:

1. A round requires a response document ID. Author disposition may be null only with a no-change reason. A review can fail, cancel or be interrupted before a reviewer responds, or after findings arrive but before an author disposition exists. Such absence is not a no-change author action. Encoding the event as a round currently requires fabricating a response or disposition reason; omitting the round loses the attempted work and exact input.
2. Every acceptance requires finalRound and reviewer-decision evidence, while human-artifact-acceptance explicitly permits a direct exact-subject human statement. An otherwise authentic human-only acceptance can have neither reviewer nor review round. The adapter would have to invent reviewer consensus or reject a supported evidence variant.
3. Every revision requires repository/path/commit/digest. Manual historical review can have reviewed uncommitted bytes, as round 1 of this very SAR did. A later immutable snapshot can preserve those exact bytes but its commit is archival evidence, not a commit that existed as the reviewed source. The current revision shape does not distinguish these identities. Treating the snapshot commit as the historical reviewed commit fabricates provenance; refusing it prevents faithful backheal even when exact original bytes and their digest are available.

**Required change:** Define variant-specific required/nullable fields and explicit reasons. A pending/interrupted/failed/cancelled attempt must retain its real input and events with unavailable response/disposition references, without asserting no-change. Separate reviewer-consensus acceptance requirements from human-only acceptance evidence and avoid invented finalRound/reviewer fields. Represent a reviewed input as either an existing pinned Git object or an explicitly uncommitted/digest-bound input with a separately identified, later published immutable snapshot. That snapshot must match the reviewed raw digest and must never imply the source commit existed at review time. Preserve exact input identity and qualify the File Under Review label/link accordingly. Missing original bytes still refuse fabrication; only verified archival copies may fill the snapshot role.

**Acceptance examples:** Add envelope fixtures for failure before first response, interruption after findings before author action, human acceptance with no review rounds, and this SAR's uncommitted round-1 input archived later. All must preserve real evidence, outcome and chronology without manufactured reviewer documents, no-change actions or historical commits. This is contract design work, not a request to implement tests during Refine.
