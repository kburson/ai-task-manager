### Important — SAR-IMPL-R1-F001 · P2

**Preserve nullable and omitted audit baseline values instead of falling back to current fields on retry.**

Primary location: [inflate-estimate.mjs:375](/Users/kpburson/.codex/worktrees/2163-inflation-intent/ai-task-manager/scripts/task-tracker/verbs/inflate-estimate.mjs:375), especially lines 382–383.

The retry preparation uses:

```js
beforeSize: baseline?.size ?? before.size,
beforeEstimate: baseline?.estimate ?? before.estimate,
```

A captured baseline member may legitimately be `null`. These expressions treat that sealed value as absent and substitute the current field. If a permitted pending field has already reached its intended value while the audit remains unapplied, the regenerated audit differs from the original sealed audit. The shared writer then refuses with `estimate-publication:before-manifest-drift`.

A concrete valid source shape is:

- An otherwise valid, owned fixture issue with its current plan and configured project membership.
- Project Estimate `2`, with no Size field value.
- A valid body field record containing `estimate: 2, size: null`.
- One valid noncontributing refine-marker comment.

This is not inherently unavailable authority. The production collector normalizes an absent project Size to `null` at [decomposition-authority.mjs:199](/Users/kpburson/.codex/worktrees/2163-inflation-intent/ai-task-manager/scripts/task-tracker/lib/decomposition-authority.mjs:199), compares body/project values using `?? null`, and does not classify a null size alone as unavailable. The shared writer captures `{ estimate: 2, size: null }` at [estimate-writer-publication.mjs:411](/Users/kpburson/.codex/worktrees/2163-inflation-intent/ai-task-manager/scripts/task-tracker/lib/estimate-writer-publication.mjs:411).

However, the separate `projectValuesForIssue` reader omits absent fields at [github-projects.mjs:170](/Users/kpburson/.codex/worktrees/2163-inflation-intent/ai-task-manager/scripts/gh/lib/github-projects.mjs:170). Initial audit preparation therefore sees `before.size === undefined`. After an interruption before audit application, moving the still-pending Size to intended `M` makes the retry render `M` as the old size instead. Its audit seal no longer matches.

There is a related representation of the same defect: omit `size` from the body field values instead of storing explicit null. The collector treats these representations equivalently, but the writer’s strict equality check does not capture `fieldBaseline` at all. That loses the fallback anchor for every audit baseline member.

**Impact:** An admitted publication can become unretryable under the partial-field convergence already supported and tested by this change. It fails closed, so this is a correctness/recovery defect rather than an authority bypass. Existing partial-field tests at [inflate-estimate-drift-cases.mjs:90](/Users/kpburson/.codex/worktrees/2163-inflation-intent/ai-task-manager/scripts/tests/integration/task-tracker/inflate-estimate-drift-cases.mjs:90) exercise only non-null `S/2` baselines.

**Required remedy:** Establish one consistent audit baseline at initial preparation and preserve it on retry, including nullable members and equivalent omitted-field representations. Distinguish a captured object containing nulls from an uncaptured `fieldBaseline === null`. Do not merely replace `??` with an object-presence check: that alone can change an initially rendered `undefined` into `null` on retry. Preserve historical intended digests and effect seals; do not repair this by resealing a pending operation.

**Required validation:** Add failing-first production-path coverage for size-null, estimate-null and relevant omitted-field variants. Demonstrate actual registered Start and initial pending-publication admission before counting the failure as RED. Interrupt before audit application, apply permitted intended field combinations, and require exact retry completion with unchanged operation, creation time, intended digest and audit seal, at-most-once business effects, and a write-free completed repeat. Retain refusal coverage for missing or inconsistent historical evidence.

This finding is established by static source tracing. I did not run its reproduction because this reviewer is prohibited from running tests.
