## Required finding

### SAR-PLAN-R2-F001 — P1 — Account for legitimate proposal-retirement transitions in the pending completion comparison

**Affected plan:** Lines 96-105, especially the instruction at line 98 to retain all current source observations, reuse the ordinary audit-hash/field projection, and refuse any remaining full-digest difference. This is a refinement of unresolved SAR-PLAN-R1-F002, not permission to weaken its unrelated-source drift requirement.

**Why the current calculation is insufficient:** The source proposal list is not invariant throughout an authorized field update. The production collector may temporarily restore a Planned Estimate proposal that was absent at initial collection and will be absent again at completion. Projecting the field snapshots back to their intended values without recomputing that legitimate parser retirement state retains the temporary proposal in the forecast digest, causing a false drift refusal.

**Source evidence:**

- `decomposition-authority.mjs:237-310` obtains the active forecast and supplies `published`, current board/body values and the actual publication-bearing issue body to `collectDecompositionCommentProposals`.
- At `decomposition-authority.mjs:408-422`, a Planned Estimate equal to the published forecast is omitted when the current board/body values match that forecast, or when `confirmedEstimateProjectionRevision` validates a confirmed later revision.
- `decomposition-publication-inputs.mjs:8-31` requires both project and body values to equal the publication proposal and requires confirmed project-estimate/body-fields effects for that later-revision condition.
- `intendedPublishedRevisionInput` at `estimate-writer-publication.mjs:55-102` projects estimate/size and `observedProjections`, but preserves the already collected `forecast.proposals` array. It does not rerun proposal retirement.
- The collector records `authority-conflict` for intermediate project/body/forecast disagreement (`decomposition-authority.mjs:586-647`). Therefore allowing that reason after validating the actual field values, as line 98 now does, is necessary but does not also repair the temporary proposal membership in the comparison image.

**Concrete static counterexample:**

1. Begin with a valid active/ready forecast for M/4h, a corresponding Planned Estimate of M/4h, and matching board/body M/4h. The target proposal is correctly absent from the initial authoritative `forecast.proposals` because `adaptiveConfirmed` is true.
2. Start a new inflation to M/6h. Its sealed intended forecast retains that absent proposal and predicts the audit and M/6h projections. This is consistent with the accepted new-operation rule: invent no observation when the comment did not initially contribute.
3. After the audit and board estimate are applied, interrupt before the body-fields effect, leaving board M/6h and body M/4h. No external source changed; every value is within the sealed permitted sets.
4. A real collection now includes the target Planned Estimate proposal: the fields no longer both equal the published M/4h forecast, and the M/6h revision has not yet acquired confirmed body-fields authority. All source reads can still be observed, with the overall `authority-conflict` caused by these permitted intermediate values.
5. Line 98's comparison updates the target hash and projects board/body snapshots to M/6h, but the reused generic helper retains the newly present proposal. That forecast digest differs from the sealed intended forecast, which had no proposal. The validator consequently refuses a clean retry. Because the callback also runs at existing effect checkpoints, the same intermediate state can stop an uninterrupted operation before the next effect.
6. If the ordinary remaining fields effect were allowed to complete and become confirmed, the production parser would retire the proposal again through `confirmedEstimateProjectionRevision`; final collection would then match the original intended membership.

This is static source analysis, not an executed test. The currently configured `estimationRubricIssue: 0` does not remove this package behavior: stored forecast records still pass through this collector, and the public package also supports projects with configured adaptive estimation. Task 1's explicit no-active-forecast seed cannot exercise this counterexample.

**Required remedy:** Refine the bounded completion comparison so it accounts for the production parser/retirement consequences of only the already sealed audit/field/confirmation transitions. State exactly which complete source bytes, published forecast identity and publication context it needs, how those values are validated against the real current collection and sealed records, and how it obtains the production parser's completed proposal membership without mutating actual authority or replacing the sealed intended digest. Merely projecting scalar field snapshots is insufficient. Do not blindly remove an extra proposal because that makes the digest match; unrelated source additions/removals or changed bytes must still refuse. Also do not simply reject every operation with an active forecast or narrow the public retry promise without an explicit specification disposition.

Keep the new-operation semantic comparison with retirement disabled separate from this completed-state retirement calculation. The former detects changed proposal semantics; the latter predicts the existing parser's legitimate contribution state under proven sealed effects. If the solution requires a contract change rather than a plan refinement, provide a targeted specification revision for review instead of silently changing authority semantics.

**Validation:** Add a real-collector/public-entry case with a valid active/ready forecast and an initially retired matching Planned Estimate. Prove both uninterrupted completion and retry after each relevant intermediate field/confirmation boundary, including board-new/body-old and fields-applied-before-confirmation. Final proposal membership and full collected/sealed digest must match. Pair the same fixtures with the separate-comment byte-change negative and unrelated proposal insertion/removal negatives, preserving the zero-new-write refusal and immutable sealed intent. Add focused pure tests for completed proposal membership, but do not replace the public collector with a canned forecast. Retain the no-active-forecast original RED as its own unchanged evidence case.
